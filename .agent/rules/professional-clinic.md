# Professional Clinic Workspace Rules

You are the implementation agent for the "Professional Clinic" plan of the EcoDigiTech DoctorSite Platform.
brain/ is the source of truth. Edit deltas; never regenerate unchanged docs.

R1  SCOPED READING. Before any task read ONLY brain/00_MASTER_RULES.md + the sections the task lists in `reads:` + the task. Never load all docs. If information is missing: do not ask, apply the nearest rule, write DECISION-NEEDED:, continue.
R2  ONE TASK AT A TIME. One microtask (<= 2 h) = one branch/commit (Conventional Commits). After the walkthrough, STOP. Never start the next task or milestone without the words "continue".
R3  NO STACK DRIFT. Fixed stack: pnpm + Turborepo; Next.js App Router, TypeScript strict; PostgreSQL 16 standard SQL (pg + PgBouncer, Drizzle, plain .sql migrations, RLS); Upstash Redis; pg-boss; Resend; Razorpay; Cloudflare + R2; Vercel; GitHub Actions Docker renderer. Changing anything needs a new ADR first.
R4  ARCHITECTURE RULE. The public site (apps/site-template) is statically generated and has no server code and no database connection of its own. Everything dynamic lives in the control plane (apps/platform), which is database-backed. The static site talks to the control plane only through versioned public APIs (/v1/public/...) with static fallbacks (tel:, wa.me, mailto) when the API is down.
R5  NO FAKE FEATURES. Nothing is "done" if it is a mock, a hardcoded array, a placeholder button, a TODO, or lorem ipsum. Every button either works end to end or does not exist.
R6  LIVE-WIRING PROOF. For every CMS-editable field there must be a Playwright test: edit in the CMS -> save -> publish -> open the LIVE preview/production URL -> assert the change is visible. A field without this test is not shippable. Likewise: public form submit -> row in Postgres -> visible in the CMS dashboard.
R7  UI QUALITY BAR (lessons from the failed first build, all are blockers):
    - CSS must actually load. Verify the compiled stylesheet is linked and non-empty in the built output; CI fails the build if the page renders unstyled (Playwright check on computed styles).
    - NO emoji anywhere as icons, bullets, nav items or status markers. Use ONE SVG icon family (Lucide or Phosphor, a single weight, 20/24 px grid) imported as components. Brand marks are SVG.
    - The site must not look machine-generated: no generic purple/blue gradients, no identical rounded-card grids, no stock "Welcome to our website" copy, no lorem ipsum, no default component-library look. Follow the visual direction in brain/08_UI_SPEC.md and ADR-013 (green/teal clinical palette, split hero with doctor photo on a rounded shape, poster-style contact rows, name plate), refined with: one display + one text typeface (self-hosted, Devanagari fallback), an 8-pt spacing scale, a type scale, consistent radii and shadows from design tokens only, real clinic content from the content sheet, generous whitespace, restrained motion (<= 200 ms, respects prefers-reduced-motion).
    - The CMS must look like premium software: a proper sidebar with icon + label, breadcrumbs, page headers with actions, dense but readable tables, empty states, skeleton loaders, toasts, confirm dialogs, keyboard focus styles, dark mode via tokens. No inline styles, no raw browser-default controls.
R8  VERIFY VISUALLY. After every UI task use the browser agent to capture screenshots at 360, 768 and 1280 px (both themes; CMS light and dark) and attach them as evidence. Fix visible defects before reporting done.
R9  SECURITY AND PRIVACY. Server-side validation with zod on every input; parameterized queries only (no raw SQL strings); RLS on every tenant table; patient name/phone/email/message encrypted (AES-256-GCM) and never logged; CSRF protection on all mutations; strict CSP; rate limits on public endpoints; secrets only in environment variables; synthetic test data only (+91 sample numbers). DPDP Act 2023: consent checkbox + notice on every form, retention and deletion workflow.
R10 MEDICAL CONTENT. No curative claims, outcome guarantees, before/after, or patient outcome testimonials. Testimonials need recorded consent and moderation.
R11 DOCS WITH CODE. Every behaviour change updates the doc it touches, appends to brain/16_CHANGELOG.md, and files an ADR when a choice changes. CI fails PRs that change code without a changelog entry.
R12 DEFINITION OF DONE for a task: typecheck, lint, unit + integration tests green; E2E proof per R6 where applicable; screenshots per R8; Lighthouse mobile perf >= 90 and a11y >= 95 for the public site (LCP < 2.0 s, CLS < 0.1, JS <= 170 KB gz per page); API P99 < 300 ms; walkthrough artifact listing evidence for each acceptance checkbox.
R13 IMMUTABLE COMMERCIAL FACTS. Basic Presence and any other existing plan facts in brain/01_PRD.md § 2 are not edited and not duplicated elsewhere. This plan is added as its own table.
R14 HONESTY. If something cannot be verified, say so in the walkthrough. Never claim a test passed that was not run.
